# Arkn.SourceGen

Roslyn Source Generator that eliminates Error factory boilerplate.

## Installation

```bash
dotnet add package Arkn.SourceGen
```

> Arkn.SourceGen is a development-only dependency and does not ship in your output assembly.

## Usage

Mark a `static partial` class with `[ArknErrors]` and declare partial methods with `[ArknErrorCode]`:

```csharp
using Arkn.SourceGen;
using Arkn.Results;

[ArknErrors]
public static partial class UserErrors
{
    [ArknErrorCode("NotFound", "User was not found")]
    public static partial Error NotFound(string? detail = null);

    [ArknErrorCode("Validation", "Email address is not valid")]
    public static partial Error InvalidEmail(string? detail = null);

    [ArknErrorCode("Conflict", "A user with this email already exists")]
    public static partial Error EmailConflict(string? detail = null);
}
```

The generator produces:

```csharp
// <auto-generated by Arkn.SourceGen />
public static partial class UserErrors
{
    public static partial Error NotFound(string? detail = null) =>
        Error.NotFound("UserErrors.NotFound", detail ?? "User was not found");

    public static partial Error InvalidEmail(string? detail = null) =>
        Error.Validation("UserErrors.InvalidEmail", detail ?? "Email address is not valid");

    public static partial Error EmailConflict(string? detail = null) =>
        Error.Conflict("UserErrors.EmailConflict", detail ?? "A user with this email already exists");
}
```

## Generated error codes

Error codes follow the **ARK002** convention: `ClassName.MethodName` — always dot-separated PascalCase, machine-readable and consistent across your codebase.

## Supported ErrorTypes

| String | Maps to |
|---|---|
| `"NotFound"` | `Error.NotFound(...)` |
| `"Validation"` | `Error.Validation(...)` |
| `"Conflict"` | `Error.Conflict(...)` |
| `"Unauthorized"` | `Error.Unauthorized(...)` |
| `"Forbidden"` | `Error.Forbidden(...)` |
| anything else | `Error.Failure(...)` |

## Integration with Arkn.Analyzers

ARK002 validates generated error codes automatically — since codes are derived from `ClassName.MethodName`, they always comply with the naming convention.
