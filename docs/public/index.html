ARK001

ErrorGroup required error

Errors must be defined in a static error group class. Inline Error.* calls are not allowed.

ARK002

Error code format error

Error codes must follow Namespace.Reason convention.

ARK003

Result not unwrapped error

Do not access .Value directly. Use .Match() to consume results.

ARK004

Job return type error

IArknJob.ExecuteAsync must return Task<Result>, never Task.

ARK005

Avoid raw HttpClient warning

Use AddArknHttp<TClient>() instead of injecting or instantiating HttpClient directly.

ARK006

Use IArknLogger warning

Prefer IArknLogger over MEL ILogger or Console.Write in Arkn-managed components.

ARK007

No throw in domain error

Domain methods must not throw. Return Result.Failure(Error.Failure(…)) instead.

ARK008

Catch must propagate warning

try/catch blocks that swallow errors without returning Result.Failure are flagged.

💥

Exceptions as control flow

A missing record throws KeyNotFoundException up 3 layers. Nobody knows it's expected.

❓

Implicit contracts

Your service returns User?. Is null "not found", "not loaded", or "access denied"? Nobody knows until runtime.

⚓

Framework gravity

You add retry, you get Polly. You add jobs, you get Quartz with database tables. The framework dominates the codebase.

Arkn answers all three. Result<T> makes failures visible. Conventions make contracts readable. Zero lock-in means every dependency is a choice.

public sealed class PaymentsClient(IArknHttp http)
    : ArknHttpClient(http, "https://api.payments.com")
{
    public Task<Result<Payment>> GetAsync(Guid id) => GetAs<Payment>("/payments/{id}", id);
    public Task<Result<Payment>> CreateAsync(PaymentRequest r) => PostAs<Payment>("/payments", r);

    .WithResponseCaching()

Arkn.Jobs v—
In-process cron scheduler with retry, timeout, distributed lock, persistence (IJobHistoryStore), and DLQ for failed jobs. ARK004 enforces Task<Result> return types at compile time.
dotnet add package Arkn.Jobs
jobscronschedulerin-processretrypersistencedistributed-lockdlq
Code example
csharp
// Job — ARK004 enforces Task<Result> return type
public class InvoiceJob(IArknLogger logger) : IArknJob
{
    public async Task<Result> ExecuteAsync(ArknJobContext ctx)
    {
        logger.Info($"Processing. RunId={ctx.RunId}");
        await ProcessAsync(ctx.CancellationToken);
        return Result.Success();
    }
}

// Registration
services.AddArknJobs(jobs =>
{
    jobs.Add<InvoiceJob>("0 2 * * *")
        .WithRetry(maxAttempts: 3)
        .WithTimeout(TimeSpan.FromMinutes(10))
        .NotifyOn(JobEvent.Failed | JobEvent.TimedOut);
    jobs.OnFailure<SlackNotifier>();
});

Rules reference
csharp — before / after
// ❌ ARK001 — inline Error.* call (not in an ErrorGroup)
return Error.NotFound("User.NotFound");

// ✅ Correct — defined in a static error class
public static class UserErrors
{
    public static Error NotFound(Guid id) => Error.NotFound("User.NotFound", $"User '{id}' not found.");
}

// ❌ ARK003 — accessing .Value without checking
var user = result.Value;

// ✅ Correct — exhaustive match
var user = result.Match(onSuccess: u => u, onFailure: _ => null);

// ❌ ARK004 — job returning Task instead of Task<Result>
public async Task ExecuteAsync(ArknJobContext ctx) { ... }

// ✅ Correct
public async Task<Result> ExecuteAsync(ArknJobContext ctx) { ... }

How Arkn.Results isolates source failures
csharp — HackerNewsSource.cs
public async Task<Result<IReadOnlyList<FeedItem>>> FetchAsync(CancellationToken ct)
{
    try
    {
        var response = await http.GetFromJsonAsync<HnResponse>(Url, ct);
        if (response is null)
            return Result.Failure<IReadOnlyList<FeedItem>>(
                Error.Failure("HN.Empty", "Empty response"));

        return Result.Success(response.Hits.ToFeedItems());
    }
    catch (HttpRequestException ex)
    {
        // Failure is returned — not thrown.
        // RefreshFeedJob logs and continues to the next source.
        return Result.Failure<IReadOnlyList<FeedItem>>(
            Error.Failure("HN.HttpError", ex.Message));
    }
}
Why it matters — Five external sources. Any can go down. Result<T> makes that an explicit, composable outcome instead of a silent crash.
